# 对外契约（冻结）

> **状态：已冻结**。本文档描述内核对外暴露的 HTTP 契约与事件契约。
> Web / CLI / 编辑器插件 / CI 等所有客户端一律基于本契约开发。
>
> **修改规则**：只允许**新增**（新路由、新事件类型、新可选字段）；
> 破坏性变更需同步提升版本号（`/api/v3`）并保留旧版本的过渡期。
> 请勿在未更新本文档的情况下改动契约。

---

## 1. 设计原则

1. **单一入口**：所有能力通过 `KernelFacade` 暴露，客户端不得直接依赖 `kernel/` 内部模块或旧 `Agent/` 代码。
2. **唯一版本前缀**：当前为 `/api/v2`。旧 `/api/*` 已废弃，不再提供。
3. **事件驱动**：审查过程通过 SSE 推送事件流，客户端按 `seq` 顺序消费。
4. **本地优先**：契约面向本机服务（默认 `http://127.0.0.1:54321`），不做多租户/鉴权设计。

## 3. SSE 事件契约

### 3.1 传输格式

`GET /api/v2/reviews/{run_id}/stream`，`Content-Type: text/event-stream`。

每个事件为一行 `data:` 前缀的 JSON 后接空行：

```
data: {"id":1,"run_id":"run_x","session_id":"sess_y","seq":1,"type":"review.started","created_at":"...","stage":null,"payload":{...}}

```

响应头固定包含：

```
Cache-Control: no-cache, no-transform
Connection: keep-alive
X-Accel-Buffering: no
```

### 3.2 事件信封（WorkflowEvent）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int \| null | 存储层自增 ID |
| `run_id` | str | 运行 ID |
| `session_id` | str | 会话 ID |
| `seq` | int | **单调递增序号，客户端据此排序与去重** |
| `type` | str | 事件类型（见 3.3） |
| `created_at` | str | ISO 8601 时间戳 |
| `stage` | str \| null | 关联阶段或通道，可为 null |
| `payload` | object | 类型相关的负载 |

> 客户端消费约定：若收到 `seq <= last_seq` 则丢弃；若收到 `seq > last_seq + 1`，
> 说明中间事件尚未到达，应按 `seq` 缓存并等待补齐后再按序上抛。

### 3.3 事件类型

**运行生命周期**

| 类型 | stage | 关键 payload |
|---|---|---|
| `review.started` | null | `request`（本次请求参数）、`trace_id` |
| `review.completed` | null | `artifact_id`、`content_preview`（报告前 500 字） |
| `review.failed` | null | `error` |

**流水线**

| 类型 | stage | 关键 payload |
|---|---|---|
| `pipeline.started` | null | `trace_id`、`stage_count`、`stages`（阶段类名列表） |
| `pipeline.completed` | null | `trace_id`、`metrics`（含各阶段耗时） |
| `pipeline.failed` | 失败阶段名 | `trace_id`、`failed_stage`、`error`、`error_mode`、`retries`、`metrics` |

**阶段**

| 类型 | stage | 说明 |
|---|---|---|
| `stage.started` | 阶段名 | 阶段开始 |
| `stage.finished` | 阶段名 | 阶段结束 |
| `stage.retry` | 阶段名 | 重试（`retry`、`max_retries`、`error`） |
| `stage.degraded` | 阶段名 | 降级继续（`error`） |

阶段名取值：`diff_collection` / `llm_setup` / `intent_analysis` / `planner` / `fusion` / `reviewer`

**增量输出**

| 类型 | stage | 说明 |
|---|---|---|
| `review.delta` | `intent` \| `review` \| `rule` | 流式增量。`intent` / `review` 携带 `content_delta`、`reasoning_delta`；`rule` 携带规则层事件 |

**静态扫描（旁路）**

| 类型 | stage | 说明 |
|---|---|---|
| `scan.started` | `scan` | 扫描开始 |
| `scan.progress` | `scan` | 扫描进度 |
| `scan.finished` | `scan` | 扫描结束 |

**工具**

| 类型 | stage | 说明 |
|---|---|---|
| `bundle_item` | 调用方指定 | 上下文包条目上报（`unit_id`、`final_context_level`、`location`） |

## 4. CLI 契约

安装（`pip install -e .`）后可用：

```bash
deltaconverge review --project-root <PATH> [--model M] [--diff-mode MODE]
                     [--enable-static-scan] [--session-id ID]
deltaconverge qa <run_id> "<question>"
deltaconverge sessions [--limit N]
deltaconverge config_doctor
```

CLI 与 Web 走**同一个 `KernelFacade`**，不构成第二套业务实现。

| 内容 | 位置 |
|---|---|
| 会话 / 运行 / 事件 / 消息 | `data/kernel/kernel.db`（SQLite） |

## 6. 扩展契约（内核端口）

新增客户端或替换实现时，只需实现/依赖 `kernel/ports/` 中的 Protocol：

| 端口 | 职责 |
|---|---|
| `GitPort` / `DiffPort` | Git 操作与 diff 上下文构建 |
| `ContextPort` / `PromptPort` | 上下文装配与提示词构建 |
| `LLMPort`（`LLMClientPort` / `LLMFactoryPort`） | 模型调用与客户端装配 |
| `StreamPort` | 流式响应处理 |
| `ToolRegistryPort` / `ToolRuntimePort` / `ToolPolicyPort` | 工具注册、执行与策略 |
| `ConversationPort` | 对话历史管理 |
| `ConfigPort` / `ProjectPort` / `RulePort` | 配置、项目、规则成长 |
| `RuntimeContextPort` | 运行时全局状态收口 |
| `ScanServicePort` / `ScanRunnerPort` | 扫描结果查询 / 扫描执行 |
| `SessionStore` / `ArtifactStore` | 持久化 |
| `IntentEnginePort` / `PlannerEnginePort` / `FusionEnginePort` / `ReviewerEnginePort` | 审查链路四个引擎 |

**约束**：`kernel/application` 与 `kernel/domain` 不得直接 `import Agent.*`
（由 CI 强制守卫）；旧实现一律通过 `kernel/infrastructure` 的 Legacy 适配器桥接。
